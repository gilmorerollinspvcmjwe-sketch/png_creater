# 游戏UI素材处理系统 — 工业级升级设计方案

## 一、产品定位与设计理念

### 1.1 产品定位
面向游戏开发者和美术人员的**专业级**游戏UI素材处理工具，覆盖「拆分→抠图→命名→导出→合并」全工作流。

### 1.2 设计理念
- **专业感**：参考 Figma/Photoshop 的深色主题、分组面板、属性检查器
- **效率优先**：键盘快捷键、鼠标交互、批量操作、实时预览
- **渐进式复杂度**：新手用默认参数一键出图，专家可精细调节每个参数
- **视觉一致性**：统一的色彩系统、间距系统、组件库

## 三、功能模块详细设计

### 3.1 放大镜取色器组件 (`magnifier.js`)

**交互设计：**
- 当进入取色模式时，鼠标悬浮在图片上自动显示放大镜
- 放大镜为 140×140 圆形，8倍放大
- 显示像素网格线（半透明白色）
- 中心像素十字准星高亮（红色边框）
- 放大镜位置：鼠标右上方偏移，避免遮挡取色点
- 底部显示当前像素坐标和RGB值
- 点击确认取色，Esc取消

**技术实现：**
```
组件接口:
  magnifier.enable(canvas, onPick, options)
  magnifier.disable()
  magnifier.setZoom(level)  // 4x/8x/16x

参数:
  canvas: 目标canvas元素
  onPick: (color: {r,g,b}, x, y) => void
  options: { zoom: 8, showGrid: true, showInfo: true }

内部实现:
  - mousemove: 从原图canvas截取区域 → 绘制到magnifier canvas
  - click: 取色回调
  - mouseleave: 隐藏放大镜
  - 键盘Esc: 取消取色模式
```

**应用场景：**
- 单图模式：背景色取色、纯色取色
- 拆分模式：背景色取色、轮廓色取色、内部背景色取色、内部轮廓色取色

### 3.2 异形检测算法（迭代BFS + 轮廓色标注）

**算法流程：**

```
输入: 原图像素数据 + 用户标注的背景色 + 用户标注的轮廓色(可选) + 参数

Step 1: 像素分类
  for each pixel:
    if 接近轮廓色 → mask[i] = WALL(2)      // 墙壁，阻断BFS
    elif 接近背景色 → mask[i] = BG_CANDIDATE(3)  // 候选背景
    else → mask[i] = FOREGROUND(1)               // 前景

Step 2: 形态学预处理（可选）
  闭运算(1px) → 桥接前景中的细小间隙，避免同一素材被分裂

Step 3: 从图片边缘BFS扩散
  queue = [所有边缘的BG_CANDIDATE像素]
  BFS: 只通过BG_CANDIDATE扩散，WALL阻断
  扩散到达的BG_CANDIDATE → 确认为真正背景(mask=0)
  未到达的BG_CANDIDATE(被轮廓包围) → 转为前景(mask=1)
  WALL → 转为前景(mask=1)

Step 4: 膨胀/腐蚀调整
  dilatePx > 0: 膨胀前景，补全缺口
  dilatePx < 0: 腐蚀前景，去毛刺

Step 5: 闭运算（连通性分析用）
  对mask做闭运算 → closedMask
  用closedMask做BFS找连通区域
  但提取像素时用原始mask（保留精确形状）

Step 6: 连通区域BFS
  对closedMask做8-连通BFS，找到所有独立连通区域
  每个连通区域: 收集所有像素 → 计算boundingBox → 计算面积

Step 7: 区域过滤
  过滤掉面积 < minArea 的区域
  过滤掉触边且长宽比>5的条状伪区域

Step 8: 精确像素回收
  对每个连通区域，从closedMask的像素出发
  BFS扩展到原始mask中相邻的前景像素
  确保原始形状的精确性

输出: regions[] — 每个包含 pixels, pixelSet, bounds, area
```

**Worker 消息协议扩展：**
```js
// 新增消息类型
worker.postMessage({
  type: 'irregularDetect',
  data: {
    imageData: { width, height, data },
    bgColor: {r, g, b},           // 用户标注的背景色
    outlineColor: {r, g, b} | null, // 用户标注的轮廓色（可选）
    outlineTolerance: 80,          // 轮廓色容差
    sensitivity: 30,               // 检测灵敏度 (1-100)
    minArea: 100,                  // 最小区域面积
    dilatePx: -1,                  // 膨胀/腐蚀量 (-5~10)
  }
});

// 返回
self.postMessage({
  type: 'irregularDetectResult',
  regions: [{
    id, pixels: [[x,y],...], pixelSet: Uint8Array,
    bounds: {x, y, w, h}, area, color
  }]
});
```

### 3.3 内轮廓抠图 (`innerContourRemover.js`)

**应用场景：**
游戏素材（如角色图标）内部有"空洞"——被前景包围的背景区域（眼睛、嘴巴、装甲间隙等），需要将这些内部背景也去除。

**算法流程：**

```
输入: 某个已检测区域 + 内部背景色 + 内部轮廓色(可选) + 参数

Step 1: 构建局部mask
  在区域的boundingBox内构建局部坐标系
  区域内的像素标记为1（前景）

Step 2: 识别内部背景候选
  对区域内每个像素:
    if 接近内部轮廓色 → 标记为WALL(3)，阻断内BFS
    elif 接近内部背景色 → 标记为INNER_BG_CANDIDATE(2)

Step 3: 从区域边界BFS
  从boundingBox的四条边出发
  只通过INNER_BG_CANDIDATE扩散，WALL阻断
  扩散到达的 → mask=4（区域边缘的缝隙背景，也应去除）
  未到达的 → mask=2（被内部轮廓包围的真正内部背景）

Step 4: 移除
  mask=2 和 mask=4 的像素都从区域中移除
  更新区域的pixels、pixelSet、bounds、area

Step 5: 内部膨胀/腐蚀
  innerDilatePx > 0: 膨胀内部前景
  innerDilatePx < 0: 腐蚀内部前景

输出: 更新后的区域
```

**Worker 消息协议扩展：**
```js
worker.postMessage({
  type: 'innerContourRemove',
  data: {
    imageData: { width, height, data },
    region: { pixels, bounds, ... },
    innerBgColor: {r, g, b},
    innerOutlineColor: {r, g, b} | null,
    innerTolerance: 50,
    innerDilatePx: -1,
  }
});
```

### 3.4 形态学运算模块 (`morphologicalOps.js`)

**提供工具函数（主线程和Worker共享逻辑）：**

| 操作 | 函数 | 参数 | 用途 |
|------|------|------|------|
| 膨胀 | `dilate(mask, w, h, radius)` | radius: 1-5 | 扩大前景，补全缺口 |
| 腐蚀 | `erode(mask, w, h, radius)` | radius: 1-5 | 缩小前景，去毛刺 |
| 闭运算 | `close(mask, w, h, radius)` | radius: 1 | 先膨胀后腐蚀，桥接间隙 |
| 开运算 | `open(mask, w, h, radius)` | radius: 1 | 先腐蚀后膨胀，去噪点 |

**UI参数整合：**
- 单图模式：在"去边强度"旁增加「膨胀/腐蚀」滑块 (-5 ~ +10)
- 拆分模式：异形检测面板中已有 dilatePx 参数
- 批量模式：精度预设中增加对应的形态学参数

### 3.5 矩形选框交互 (`rectSplitter.js`)

**功能：**
- 在图片上拖拽绘制矩形选框
- 选框可调整大小（四角拖拽手柄）
- 选框可移动（拖拽选框内部）
- 键盘微调（方向键±1px，Shift+方向键±10px）
- 选中选框Delete键删除
- Esc取消选中

**自动网格：**
- 输入行列数 → 自动生成N×M等分选框
- 支持不等间距网格（后续扩展）

**Canvas叠加层架构：**
```
<mainCanvas>        ← 底层：原图/处理后图
<overlayCanvas>     ← 顶层：选框/区域标注/交互反馈（透明背景）
```
- overlayCanvas 绝对定位在 mainCanvas 之上
- 鼠标事件绑定在 overlayCanvas
- 每次交互后只重绘 overlay，不影响底层

## 六、Worker增强方案

### 6.1 现有功能保持
- `processImage`: 背景去除（auto/white/solid/checkerboard/transparent）
- `detectAssets`: 连通区域检测

### 6.2 新增消息类型

| 消息类型 | 输入 | 输出 | 用途 |
|---------|------|------|------|
| `irregularDetect` | imageData + bgColor + outlineColor + params | regions[] | 异形BFS检测 |
| `innerContourRemove` | imageData + region + innerColors + params | updatedRegion | 内轮廓抠图 |
| `morphOp` | mask + operation + radius | updatedMask | 形态学运算 |
| `trimTransparent` | imageData | trimmedImageData + bounds | 裁剪透明边缘 |

### 6.3 性能优化
- Worker消息中使用 `Transferable` 对象（ArrayBuffer）传输大数据，避免拷贝
- 大图（>2000px）自动降采样处理后映射回原图
- 批量模式下使用Worker池（最多 `navigator.hardwareConcurrency` 个）

## 八、与现有代码的兼容性策略

| 现有代码 | 处理方式 |
|---------|---------|
| `imageProcessor.js` Worker | 保留所有现有消息类型，新增 `irregularDetect`/`innerContourRemove`/`trimTransparent` |
| `main.js` 单图逻辑 | 逐步迁移到 `singleMode/singleController.js`，原 `main.js` 变为模式路由 |
| 批量模式四大模块 | 保持现有接口，升级CSS样式 |
| `stateManager.js` | 扩展状态结构，增加拆分/合并模式的状态 |
| `styles.css` | 拆分为模块化CSS，保留核心变量 |

**渐进式改造原则：**
- 每个阶段可独立测试，不破坏已有功能
- 新模式（拆分/合并）通过顶栏Tab扩展，与现有模式并存
- Worker增强是向后兼容的，现有消息协议不变
