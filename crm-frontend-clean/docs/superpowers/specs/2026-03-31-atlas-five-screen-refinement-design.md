# Atlas 五类页面统一收敛改造设计

## 背景

这轮改造只针对 Atlas 设计语言下的 CRM 概念页，覆盖 `Customers`、`Accounts`、`Pipeline` 三组对象的 `list / detail / create / edit / delete` 五类页面。

目标不是重做信息架构，也不是补完整交互逻辑，而是把当前页面从“设计概念展示”进一步收紧到“更像真实海外工业 B2B SaaS 产品”的状态。

## 这轮要解决的问题

当前 Atlas 页面已经具备较完整的结构，但还有几类明显问题：

- 页面主标题经常被概念名抢走，用户进入页面后不够容易判断“我现在在哪”
- 玻璃态、阴影和白色按钮偏多，界面有一点发飘
- 列表页和预览区的动作仍然偏多，主次不够明确
- 删除流程在不同对象之间不一致，客户页还出现了“Type DELETE to continue”但没有真实输入结构
- 展开类文案过于泛，不够像真实产品用语
- 筛选区和表单区虽然视觉完整，但还不够像真实产品控件

## 设计目标

### 目标 1：让页面第一眼更像工作界面

每个页面顶部先表达“当前页面 / 当前对象 / 当前任务”，而不是先表达设计概念本身。Atlas 作为环境标识保留，但降级为次级信息。

### 目标 2：让操作层级更干净

每个局部区域只保留一个最重要的主动作。其他动作优先降级为次按钮、文字按钮或 `⋯` 菜单入口。

### 目标 3：让界面更稳

Atlas 的视觉方向维持成熟、高价值、克制，但通过减少玻璃感、重阴影和重复按钮，让页面从“展示感”转向“工作感”。

### 目标 4：统一五类页面的任务感

`list` 强调浏览和筛选，`detail` 强调判断和操作，`create / edit` 强调表单任务，`delete` 只服务于风险确认。

## 范围

### 本轮包含

- Atlas 主题下的 `Customers`、`Accounts`、`Pipeline`
- 五类页面：`list / detail / create / edit / delete`
- 共享样式文件中的 Atlas 相关层级、表面、动作样式调整
- 页面标题、说明文案、局部布局和危险操作统一
- 针对本轮变化补最小测试

### 本轮不包含

- 不处理移动端
- 不改 Meridian / Foundry
- 不补完整业务交互逻辑
- 不重构成真实可提交表单
- 不新增对象或功能模块

## 统一设计规则

### 标题规则

- `list` 页：主标题直接是对象集合名，如 `Customers`
- `detail` 页：主标题直接是当前记录名
- `create` 页：主标题直接是当前任务，如 `Create customer`
- `edit` 页：主标题直接是当前任务，如 `Edit account`
- `delete` 页：主标题直接是当前风险动作，如 `Delete deal`
- `Atlas` 只保留为次级环境标签，不再占据主标题位置

### 动作规则

- 顶部区域只保留一个主按钮
- 局部卡片或预览区最多一个主按钮加一个次按钮
- 行内高频动作从并列多个按钮改成更轻的入口
- 删除操作不再与普通操作同级展示

### 表面规则

- Atlas 下减少玻璃态面板的使用频率
- 抽屉、弹窗、风险栏优先使用更实的背景和更浅的阴影
- 弱化“很多白色按钮漂浮在页面上”的感觉
- 重点依靠排版顺序、留白和标题层级建立

### 文案规则

- 页面文案用产品工作语言，不用设计说明语言
- `Show more` 改成具体对象导向的文案
- 删除确认文案统一强调对象、后果、保留选项和最终动作

## 五类页面改造方案

### 1. List 页面

#### 顶部

- 主标题显示当前对象名，如 `Customers`
- 当前位置或环境信息放在标题上方的轻量标签中显示，例如 `Atlas workspace`
- 顶部状态胶囊数量减少，只保留必要环境说明

#### 轻量摘要条

- 继续保留 KPI 条，但降级为轻摘要
- 字重、背景和视觉对比下降，不再与主工作区争抢注意力
- 摘要条只提供当前工作面的运营概览，不承担主要导航和说明职责

#### 筛选区

- 搜索、筛选、排序明确分组
- 视觉结构更接近真实控件，不再像纯展示块
- `Advanced filters` 作为补充操作保留

#### 列表内容

- 行内操作降噪，减少显式按钮数量
- 保持可扫描，但不让每一行都像独立按钮集合
- 选中态继续保留，用于支撑右侧预览

#### 预览抽屉

- 保留抽屉式快速预览
- 顶部动作收敛为一个主动作、一个次动作和 `⋯`
- 预览区减少说明性废话，更强调对象判断信息

### 2. Detail 页面

#### 顶部与主栏

- 主标题直接显示对象名
- 上方只放轻量环境标识，不再重复概念说明
- 中间主栏成为唯一阅读中心，最重要的内容优先放这里

#### 左栏

- 保留身份、状态、少量关键操作和核心指标
- 操作按钮收敛，避免左栏成为“按钮堆”

#### 右栏

- 作为支持判断的侧信息区
- 优先放风险、状态、检查项、相关对象
- 减少“解释设计意图”的说明文案

#### 展开文案

- 所有展开按钮改成具体语义，如 `Expand note`、`Show full customer note`

### 3. Create 页面

- 标题明确为当前新建任务
- 页面开头说明改成任务导向文案，而不是设计概念说明
- 分组标题更像表单步骤
- 页面只保留完成任务需要的信息，弱化旁支内容

### 4. Edit 页面

- 与 `create` 使用同一套结构，降低学习成本
- 明确展示正在编辑哪个对象
- 未保存状态保留，但不堆叠太多状态胶囊

### 5. Delete 页面

- 三组对象统一为一套危险操作框架
- 页面只服务于风险确认，不再混入不相关说明
- 如果界面不做真实输入确认，则删除“Type DELETE to continue”这类假输入提示
- 保留导出作为辅助选项，但视觉上降级
- `Cancel` 和危险按钮层级清晰拉开

## 实现方式

### 样式层

主要在共享样式文件中完成以下 Atlas 定向收敛：

- Atlas 下的面板、抽屉、弹窗、侧栏的背景与阴影调整
- 统一动作尺寸、层级和按钮密度
- 增加更明确的标题区、环境标签、局部说明和轻量分隔样式
- 为“伪控件”增加更可信的结构样式

### 页面层

分别更新：

- `CustomerConceptLab.tsx`
- `AccountConceptLab.tsx`
- `PipelineConceptLab.tsx`

每个文件都按五类页面调整标题、文案、动作数量和局部结构，但不改动整体路由方式和基础数据来源。

## 测试方案

这轮以最小回归验证为主：

- 为 Atlas 页面补关键结构和文案测试
- 覆盖主标题、删除流程统一、展开文案变化、Atlas 轻量摘要和动作收敛
- 保留现有类型检查、构建和概念页相关测试作为最终验证

计划执行：

- 先写失败测试，确认旧结构不满足新要求
- 再修改实现使测试通过
- 最后跑相关测试和构建

## 风险与控制

### 风险 1：共享样式影响非 Atlas 主题

控制方式：把明显的视觉收敛尽量限定在 Atlas 主题选择器下，不改变 Meridian / Foundry 现有方向。

### 风险 2：动作过度收缩后信息不够

控制方式：只收敛重复和噪音动作，保留对象级主动作与必要的次动作。

### 风险 3：伪控件调整后与现有测试不一致

控制方式：先补测试，围绕最终页面层级和文案做断言，不把测试绑死在旧文本上。

## 完成标准

满足以下条件即可认为这轮完成：

- Atlas 下三组对象的五类页面完成统一收敛
- 页面主标题都正确表达当前页面或对象
- 预览区、详情页和删除页的动作层级明显更清楚
- 删除流程在三组对象之间保持一致
- 玻璃态和浮层感明显收敛
- 相关测试、类型检查和构建通过
